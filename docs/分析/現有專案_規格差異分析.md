## 3. 核心差異與處理建議

### 實際模組依賴與資料流

`Domain ← AI ← Simulation ← Persistence ← Presentation／Headless`為主要依賴方向；Simulation同時直接引用Domain，Presentation／Headless也直接引用AI。Domain沒有Godot依賴。Persistence目前依賴Simulation以使用WorldCodec／Integrity，屬可運作的既有設計；若之後造成存檔測試或循環依賴，再抽快照契約，不為目錄美觀立即拆庫。

資料流為：Godot輸入／NPC觀察評分 → ActionIntent → SimulationEngine提交流程 → ActionValidator → ActionExecutor與各Actions → WorldState／帳本／工作／事件 → Snapshot與UI。設定由GameConfiguration載入，新情境按Profile覆寫並存入世界快照；不是改JSON就立即改變舊世界。Presentation位置`src/Presentation`與config位置符合分離目的，不必搬成建議中的game／content。
