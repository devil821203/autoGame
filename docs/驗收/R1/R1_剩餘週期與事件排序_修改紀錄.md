## 修改範圍

| 項目 | 原流程 | 本批程式變更 |
| --- | --- | --- |
| 宗門公告 | 每 Tick 呼叫並檢查餘數 | `SectPublication` 按原設定週期續排，沿用預算保留、數量與價格 |
| 成員考核 | 每 Tick 掃描是否到期 | 每位成員獨立 `MemberReview`；加入後登記期限、退出後取消；用帳本序號區分同一投影 Tick 內考核前後的成功交付 |
| 聚落結算 | 相容 Tick 內呼叫 | 日界 `SettlementSettlement`，沿用雜役付薪→建築生產與稅→居民消耗及人口累積；非固定日模式另排建築到期事件 |
| 測試收購 | 同一方法買入兼檢查報價 | `ProcurementPurchase` 與 `ProcurementReview` 分開，保留原每個時間步買入、原較長週期調價；同時刻先收購再調價 |
| 清剿任務 | 每 Tick 檢查公告時間 | 首次公告及後續週期獨立排程；沿用目標、期限、進度與貢獻分配 |
| 組隊 | 每 Tick 檢查邀請到期及成員關係 | 邀請保存精確秒期限，逐筆 `PartyExpiry`；成員關係在事件同步時整理；邀約／到期通知只喚醒相關角色 |
| 戰後時間 | 逐 Tick 重播相容步 | 世界事件佇列推進；`BattleCatchup` 完成補進，`BattleRelease` 解鎖參戰者忙碌期；玩家戰鬥輪數仍不推世界秒數 |
| AI 續排 | 相容步間接排空待決策 | `DecisionDrain` 在世界結算之後處理；決策預算不足時排到下一預算窗口，沒有待決策者不建立心跳 |
| 時鐘 | `CompatibilityStep` 推 Tick 再呼叫各系統 | 最新 `LifeEventScenario` 啟用 `IndependentWorldEvents`，不再排入或執行相容步；秒數為權威時間 |

## 同時刻相依順序

1. 日期與 AP 日界更新。
2. 徵集任務、社交／組隊邀請及訂單到期；完成退款／解鎖。
3. 資源再生及外部訊號：按事件序號排序。若訊號阻斷快進，其餘同秒事件保留，繼續後才結算。
4. 工作完成、恢復、交易操作、戰後解鎖；不同工作種類以提交序號排序，同序號再用事件序號。
5. 聚落結算。
6. 測試收購買入，再檢查價格。
7. 成員考核。
8. 宗門與清剿公告。
9. 宗門發薪。
10. 決策重試與待決策處理。

這是程式相依次序，不是新增玩法數值。事件仍受既有單次處理量、同時刻處理量限制；若因事件預算停止，剩餘同秒事件保留於快照。新模式保留 `Clock.Tick` 作衍生欄位，供既有帳本、日期與設定單位換算；未宣稱已刪除所有名稱含 Tick 的資料欄位。歷史情境程式未刪除，也未製作舊檔遷移。

## 參數來源與生效

沿用新局載入後的設定快照，沒有另加一套週期或價格值：

- `config/time/action-driven.json`：分鐘／時間步及每日分鐘；分鐘轉秒乘 60。
- `config/time/calendar.json`：既有日曆、AP、固定戰鬥成本。
- `config/organizations/`：既有宗門考核、公告、發薪及 `hunts.json` 清剿週期。
- `config/combat/party.json`：組隊邀請存續時間。
- `config/economy/procurement.json` 與 `config/life/procurement.json`：原收購設定與藥物模式覆寫。
- `config/settlements/operations.json`、`runtime.json`、`daily-economy.json`、`taxes.json`：原聚落生產、結算與稅設定。

沿用既有 `TimeScenario`／分鐘模式換算，事件使用換算後快照乘每步秒數，不重複把天數乘一次日長。最新 R1 新局才啟用本批整合；不是修改 JSON 後自動改寫已開啟的世界。
