## 已接入的能力

- 新建世界可明確啟用`Time.DiscreteEvents`，其`WorldTime`為單調long秒。`SimulationEngine.AdvanceTo(targetSeconds)`依到期秒／序號執行，事件執行時秒時鐘就是DueAt，不先跳到目標再補結算。
- .NET PriorityQueue穩定排序；可在處理事件時加入同時間事件，新序號排在既有事件後面。持久化只保存資料，不保存委派／Node；載入重建堆。
- 取消提升Correlation版本，舊事件出隊時丟棄；消耗過的EventId保存於快照，拒絕重放。重要訊號結算後立即返回目前秒數，同時刻尚未處理的事件保留。
- 每次推進及同時間戳事件上限受config控制；達限停在目前時間，不跳過佇列。例外回滾整份世界、待提交命令、資產、亂數與事件狀態。
- 凡人屬性、打坐及功法批次共用既有Validator／AP／成果計算，下一段直接以秒排程；新模式停用舊MortalTrainingWork掃描完成入口，避免同時結算兩次。600秒開始一段，不管是否從相容格點開始，都完整經過600秒才給成果。
- 保留批次先付全部AP、逐段體力與經驗、疲勞重算、受襲中斷不退AP；中途JSON存讀可繼續，完成一次，不重扣起始費。
- 玩家手動活動及自動畫面推進遇重要事件／預算上限會停下。UI顯示秒時鐘、HH:mm:ss、停止原因與修練下一次秒倒數。

17／30分鐘是1020／1800秒的排程測試資料；沒有新增17分鐘正式修練、沒有恢復煉丹，也沒有替非整十分鐘活動定AP取整規則。

## Godot操作

1. 正常啟動專案。
2. 按「R1秒制事件測試（重建）」：重新建立功法世界並明確啟用新模式，世界暫停；原存檔不修改。
3. 在「凡人修為」頁選擇屬性／打坐／功法，次數可用6。開始支付6AP，每600秒結算一次，總3600秒。
4. 一般查詢不推時間；主角自主排程仍可選。新模式的另一個明確時間API為`AdvanceTo(絕對秒數)`，不是現實時間。

三個主要情境預設及歷史情境仍保留原模式，不自動切換。開新存檔若來自R1世界會保留R1模式；從舊世界開新局仍沿用原情境規則。

## 相容轉接與尚未完成

`Clock.Tick`目前是`WorldTime / SecondsPerStep`的相容投影。AP日曆、原帳本／事件Tick、旅行、生活服務、藥效、聚落、薪資與任務等尚用原解析器；每600秒（由既有分鐘設定換算）排一個明確CompatibilityStep事件轉接。該事件先完成前一區間，再允許NPC決策／新工作從當下開始，避免從前一格點起算而縮短工期。

因此：

- 新頂層事件與修練可精確到秒；**Life／Travel／週期事件尚未全部拆成獨立秒事件**，轉接內仍保留舊模組結算順序，尚不能宣稱跨所有子系統完全共用SequenceId。
- 非相容邊界上的未轉接活動會被共用Validator明確拒絕，世界不推時、不扣費；不讓「17分鐘開始休息卻在20分鐘就回1AP」悄悄發生。修練可以從任意秒開始。其他活動需先由明確推進到相容邊界，或等待後續轉接。
- 舊Headless `StepValidatedBatch`不接受R1世界，須使用秒制AdvanceTo，不允許繞過事件時鐘。
- 相容事件仍會建立NPC候選／索引；完全定向決策是R3範圍，不將目前稱為已移除全體輪詢。R1還須減少不必要的相容步進與完成子系統事件拆分。
- 未重測新模式長年經濟、1k／5k容量、人工畫面及FPS。事件清單與消耗ID保留，不自行裁剪稽核資料；效能數字不從舊模式搬用。

## 設定與存檔

- `config/time/discrete-events.json`：TimeUnit必須Seconds；MaximumEventsPerAdvance／MaximumEventsAtSameTime皆正整數，工程保護上限可調。由GameConfiguration讀入、驗證、保存世界快照；只在新建R1世界讀取，舊檔不重套目前設定。
- 活動工期、AP、體力與收益仍使用既有分類設定；1分鐘=60秒屬單位轉換，不另造一份平衡值。
- 事件資料FormatVersion=1。R1使用`JsonWorldStore`寫出的檔案外部SchemaVersion=4，明確包含事件佇列／版本／消耗ID／進行中修練秒期限。舊引擎只支援1～3，會拒絕格式4，避免忽略秒資料後錯誤載入。
- Domain內部快照仍用既有WorldState schema3；持久化入口對秒制檔案寫4／讀回正規化為內部3。`WorldCodec.Serialize`是內部快照，不是R1對外另存入口；含秒佇列卻宣稱格式1～3的檔案會被拒絕，不自動修檔。
- 舊格式1～3的原模式讀取維持，無自動遷移；國家舊檔拒絕、禁丹與beast-hide等既有政策不變。另存新檔沿用CreateNew，不覆寫來源。
