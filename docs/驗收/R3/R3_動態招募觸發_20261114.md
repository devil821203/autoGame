# R3-01 動態招募觸發（2026-11-14）

本批修正已確認 R3 範圍中的「動態新增角色」缺口。組織招募一般成員時，角色加入世界後原先只有 AP 刷新，沒有 R3 首次決策請求；因為 R3 啟動時該角色尚不存在，可能永遠不會首次評估。

## 實作

`src/Simulation/OrganizationLaborActions.cs` 在角色、資源帳本、招募收據與 AP 刷新均完成後，對新角色呼叫 `EventDecisions.Request(..., Startup)`。沿用按角色去重、FIFO 序號、預算、忙碌檢查與自主權限；不直接呼叫 Planner 或直接替 NPC 下令。未啟用 R3 時 Request 保持無作用。

抽象雜役分支不建立 CharacterState，不產生 Startup。其餘 Characters.Add 位置已核對：設定載入、測試情境及規模情境是在 R3 啟動前建立角色，由 EnableFresh 統一加入；地城動態建立的是怪物，依既有規則不進一般角色決策。沒有新增其他角色生成機制。

沒有變更 config 或遊戲數值，招募費用、物資亂數、模板及 AP 沿用既有世界設定。沒有修改存檔格式、遷移舊檔或變更市場知識。

## 驗收

`tests/Acceptance/OrganizationLaborTests.cs` 新增兩項：

1. 走既有據點／宿舍／一般成員招募流程，確認僅新成員與行動者收到請求、新成員只有 Startup 原因、已有資源與 AP；序列化後與原世界同秒首次評估，trace 包含 Startup，世界 digest 相同。
2. 走雜役招募，確認雜役數增加但角色數不變，沒有 Startup 或無關角色請求。

獨立輸出建置 `bin/R3Recruit/` 零警告零錯誤，避免前輪測試輸出占用；招募篩選命令實際執行 **85/85** 通過（現有 runner 在該篩選後仍會附加其他測試，不冒稱只有招募案例）。其中兩項新增測試均有 PASS。Godot C# 建置零警告零錯誤。
