# R3-01 資源入帳與收受角色喚醒（2026-11-14）

## 目標與設計

接續 [R3 執行方案](../../方案/R3_事件決策與知識邊界_執行方案_20261110.md)。共用資源轉移原先更新帳本後，通常只由行動生命週期喚醒行動者；非行動者的實際收受角色可能仍等舊閒置重試，無法因自己的資源改變重新評估。

`ActionExecutor.Transfer` 現在於帳本入帳後檢查實際 `to` 帳戶；若為角色，加入其 `StateChanged` 請求。此機制也涵蓋透過共用 Transfer 完成的付款、預留結算或退款，收件者只知道自己的已入帳資源。怪物沿用既有 Request 過濾，不進一般 NPC 決策。

- 資源進入 escrow、消耗或組織帳戶時，不冒充角色發請求。
- 接受工作或建立預留時，尚未真正入帳的收件者不收到通知。
- 到期驗證失敗、沒有帳本轉移時，不喚醒預定收件者。
- 工作中的收件者保留請求，等待自己的完成事件再合併評估；沿用 R3-02，不直接呼叫 Planner 或替角色下令。
- 已有的發送者終態喚醒保持原規則，不對旁觀者公開私人財產。

沒有修改數量、價格、容量、費用、成功率、付款時點、AP、預留或存檔格式，沒有新增 config 參數。決策預算與重試仍使用既有世界設定。

## 驗收

1. 零工期延時轉移與有工期預留轉移：接受／預留及到期前不喚醒收件者，實際入帳後僅收受角色取得 StateChanged；餘額與快照續算一致。
2. 到期缺資源失敗：不付款、不喚醒預定收件者。
3. 轉入組織帳戶：真實入帳成功，但無組織 ID 的角色請求。
4. 收件者仍在 Wait：入帳後不提前評估；自身完成後 trace 合併 StateChanged 與 ActionCompleted，快照續算相同。
