# R3-02 佇列順序與同秒去重（2026-11-14）

依 `R3_事件決策與知識邊界_執行方案_20261110.md`，本批處理 R3-02 的實際 FIFO 傳遞與 R3-01 同秒通知合併，不增加玩法或修改數值。

## 問題與修改

1. `EventDecisions.Drain` 原先按請求 Sequence 選取角色，但將集合送入 `AutonomousDecisions.Queue` 後，又按角色 ID 與舊 DecisionCursor 重排；同一批內實際評估順序不符合 FIFO。改以有序角色清單傳遞，R3 路徑保留原序；非 R3 路徑仍沿用原游標排序。
2. 同一秒內第一次評估結束後再收到通知，原先能再次評估。同秒已有 trace 的角色現在保留請求、序號與原因，不重評；下一個既有相容步長決策窗口再處理。獨立事件模式將 DecisionDrain 排到下一窗口，避免在當秒不斷排空事件。預算已用完仍遵守原窗口限制。
3. 提前通知使原閒置 DecisionRetry 版本失效，沿用既有取消機制；本批增加驗收，確認只有一筆有效替代重試。

沒有新增持久狀態欄位、存檔格式或 config。窗口仍取世界 `DiscreteTime.SecondsPerStep`；閒置間隔仍來自已載入 `config/time/action-driven.json`／LOD 規則；決策預算仍使用 `Rules.DecisionBudget`。這是演算法順序修正，不新增平衡參數。

## 修改檔案

- `src/Simulation/AutonomousDecisions.cs`：有序 R3 請求與 legacy 游標分流。
- `src/Simulation/EventDecisions.cs`：同秒 trace 防重與 FIFO 清單傳遞。
- `src/Simulation/SimulationEngine.AdvanceTo.cs`：同秒待處理請求延後下一既有窗口。
- `tests/Acceptance/EventDecisionTests.cs`：新增四項，更新既有通知案例的同秒預期。

## 驗證

四項新測試覆蓋：

- 與角色 ID／舊游標不同的 FIFO，實際 Planner 呼叫順序與快照續算一致。
- 同秒多次 Advance 不重評；通知理由與原 FIFO 序號保留，下一窗口 trace 正確。
- 獨立事件模式不造成 drain loop，只有一筆有效下一窗口事件；快照續算相同。
- 提前通知取消舊重試，重新評估後只留一筆有效重試，理由不混入已取消的 IdleRetry。
