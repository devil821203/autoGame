# R3-02 忙碌通知保留與公平喚醒（2026-11-14）

## 目標與處理

依 [R3 執行方案](../../方案/R3_事件決策與知識邊界_執行方案_20261110.md) 接續佇列驗收。原先 Drain 遇工作中角色直接移除請求；即使完成事件會重新喚醒，原通知原因與原 FIFO 位置仍會遺失。AP 占用也會將原請求換成重試，失去原原因。

本批統一 `EventDecisions.NextDrainAt` 為可評估時間來源：

- 已有工作／休息／戰鬥完成事件者保留 Ready 中的請求，等待既有事件，不排空轉 DecisionDrain。
- 只有 AP 時間占用者保留原請求，獨立世界將 drain 排至 BusyThroughTick 對應秒數；相容世界由既有相容事件再次檢查。
- 同秒已評估與決策預算用完者仍等下一既有決策窗口。
- 忙碌隊首不阻塞後方可評估角色、不耗用評估預算；完成時以原序號取得 FIFO 優先，原因合併完成通知。
- 當新完成事件讓請求能早於既有 drain 處理時，用事件版本替換較晚的排程；舊事件失效。

通知只保留原收件者，不新增全域廣播。沒有新增 config 數值、變更行動規則、成本、AP 退款或存檔格式。

## 檔案

- `src/Simulation/EventDecisions.cs`：可評估時間與工作占用判斷；保留忙碌請求。
- `src/Simulation/SimulationEngine.AdvanceTo.cs`：排最早可評估請求，無可評估者不排 drain。
- `tests/Acceptance/EventDecisionTests.cs`：新增三項、更新一項前批忙碌排程預期。

## 驗收

新增三項覆蓋：

1. 真實 Wait 行動在相容／獨立世界期間不評估；原序號與通知原因保留，獨立世界無輪詢 drain；完成合併 ActionCompleted，快照續算 digest 相同。
2. 預算為一的情境：忙碌 NPC 隊首不阻擋自主玩家；NPC 完成後優先於後到請求，驗證 FIFO 與預算公平。
3. 僅 AP 占用在可用時間前不評估，準時評估後 trace 保留原通知，快照續算一致。此為合法預算狀態的測試 fixture，不新增正式玩法。
