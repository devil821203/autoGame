# R7 秒制引擎容量與長期量測

日期：2026-10-31。狀態：測試中；不是容量與多年驗收結案。

本次沿用R6b新世界、三地區與真實秒制事件引擎，以有限初始庫存的合成NPC增加負載。保留原有角色與內容，深複製角色可變資料，將新增NPC分散到三區城鎮；不是正式人口生成玩法。R1～R3、R5、R6b先前缺口沒有因本量測消失。

## 工具與生效方式

新增 `src/Headless/DiscretePerformanceBenchmark.cs` 及 `config/testing/r7-benchmark.json`；入口 `--r7-benchmark 輸出目錄 [單一NPC數]`。設定控制人數、決策覆蓋、安全預算、重要事件及多年探針。每次輸出目錄必須全新，避免覆寫證據。GUI的PerformancePanel增加秒制累計事件、佇列及AI指標，未自行模擬另一套規則。

本機原有Release中介檔與Debug runtimeconfig不可讀，錯誤為OneDrive提供者未執行。未刪除或覆寫原檔，使用專案內新的本地輸出建置成功，0警告、0錯誤：

```powershell
dotnet build src/Headless -c Release --artifacts-path .tools/r7-artifacts --ignore-failed-sources
dotnet .tools/r7-artifacts/bin/Headless/release/Headless.dll --r7-benchmark document/evidence/r7-measurements-20261031/新目錄
```

## 第一次完整量測結果

證據在 [run-02](../../../document/evidence/r7-measurements-20261031/run-02/)，設定、硬體與內容指紋見 `run-settings.json`。Windows X64、.NET8.0.32、20邏輯核心、Intel Family6 Model183；Release，Seed12345，內容r6b-1，三區147格，決策預算12。量測同時有完整回歸程序執行，屬共享機器負載，不宜作隔離環境容量承諾。

| 負載 | 實際步數／世界秒 | 決策覆蓋 | 步耗時平均／P95（ms） | 存／讀（ms） | 結果 |

3年目標為31,104,000世界秒，實際僅103,800秒，約1.20個世界日。不能用覆蓋100%代替多年驗收。100／1000也只有首次決策覆蓋，不代表所有角色完成完整生產經濟循環。

四個負載均通過1020秒重要事件精確停止、完整狀態驗證、SQLite完整快照雜湊相同及讀檔後一步續跑相同。事件處理／丟棄累計各25、616、76、2109；Planner調用59、359、116、1585；步末取樣佇列峰值46、130、129、54。取消／過期事件也可能計入已消費事件，不能直接解讀成成功行動數。

## 指標解讀與限制

每步計時包含引擎實際提交、複製及完整驗證，外部收集快照不計入步耗時，但計入牆鐘。未暖機，首筆含JIT；9筆的P95尤其不可當穩態效能。安全限制在步之間檢查，故實際牆鐘可能超過30秒。存讀與續跑驗證另外計時。

記憶體在存讀／續跑後取樣；run-02的 `PeakWorkingSetBytes` 是程序生命週期峰值，含前一負載，並非各負載獨立峰值。後續工具已明確命名為 `ProcessLifetimePeakWorkingSetBytes`，增加實際訂單成交數及世界秒／牆鐘秒；run-02原始資料保留、不補造欄位。步末佇列峰值不是事件內部瞬間峰值。

5千人明顯尚未達全覆蓋。現有一步仍包含全世界複製、驗證及快照收集，僅憑總耗時無法將瓶頸歸因到Planner；本次沒有關閉驗證或臆測熱點後重寫。下一步需針對複製／驗證／事件執行分段剖析，再決定最小優化，保留一致性驗收。

最終本地建置通過，0警告／錯誤；既有完整回歸431/431通過，新增R7聚焦2/2通過（完整回歸開始後新增兩項，沒有混稱433項全套）。Godot控制資格與存讀UI smoke通過、實際exit0。最終100人重跑確認明確記憶體欄位、成交數0與吞吐欄位生效，沒有將未發生成交誤報經濟循環完成。詳細指令與輸出在同證據目錄。

多年T14、5000完整覆蓋、實際畫面FPS及實機效能門檻尚未驗證／未定，R7維持測試中。Headless沒有畫面FPS；不以此恢復歷史玩法或擴充新玩法。大型SQLite檢查點僅保留本地，摘要與原始JSON／日誌受版本管理。
