狀態：**測試中／未驗證**。接續使用者確認的 R3-01「尚未修改」兩項：組隊狀態與清剿事件通知。本輪延續「先改程式，不編譯不測試」，只修改來源、做文字閱讀並更新紀錄，沒有新增或執行測試，沒有建置或啟動 Godot。歷史 578/578 不能當成本輪驗證結果。

## 組隊接線

`src/Simulation/PartyActions.cs` 增加統一通知 helper，對收件角色去重並依 ID 排序，沿用 EventDecisions.Request：

| 真正發生的事件 | 通知對象 |
| --- | --- |
| 發出邀請 | 邀請者的自身狀態、受邀者的 KnownNotification |
| 接受邀請／成隊／加入既有隊伍 | 回應者、邀請者及受影響的原隊員 |
| 拒絕邀請 | 回應者與邀請者，不廣播既有隊員 |
| 離隊／不足人數而解散／重新選定隊長 | 原隊伍全部成員，包含離隊者與留隊者 |
| 邀請真正到期 | 邀請雙方，只在 Pending → Expired 時通知 |
| 組織資格或敵對狀態導致清理隊伍 | 原隊伍成員，包含被移除者與留隊者 |
| WaitParty | 不增加隊伍狀態通知，保留原行動終態流程 |

隊伍人數、隊長繼承順序、邀約資格與期限均未調整。沒有把回應或私人邀約廣播給其他組織或旁觀者。

## 清剿接線

`src/Simulation/HuntActions.cs`：

- 真正建立 HuntMission 後，才通知既有可見範圍內的所屬組織一般存活非敵對成員。
- 接單後通知行動者自身任務狀態，不廣播私人接單操作。
- 有效擊殺更新進度及獎勵紀錄後，通知該任務的原接單者，包含此次未參戰者。
- 達成所需擊殺量時，除接單者外，也通知現有組織公告觀察者，讓候選任務可用性重新評估。
- 無有效進度、重複戰鬥紀錄或沒有新公告時，不增加通知。

公告可見邊界沿用 `ExpeditionObservations` 現有的「所屬組織」規則，沒有擅自新增同區限制、傳訊距離或新的資訊傳播玩法。原接單者依已參與紀錄取得自身任務更新；沒有向其他組織公開任務。擊殺數、期限、接單資格、貢獻點分配及戰鬥獎勵均維持原規則，不新增清剿到期排程或狀態欄位。

## 排程層去除重複通知

`src/Simulation/WorldPeriodEvents.cs` 保留原排程時間與週期，僅移除：

1. 建立組隊邀約到期事件時的受邀者通知：改由真正發出邀請時通知，相容與獨立事件模式共用。
2. 組隊到期 callback 對雙方的通知：改由 PartyActions 的實際狀態轉換處理，避免已關閉邀約誤通知。
3. 每個清剿公告週期無條件喚醒整個組織：改由實際建立公告／更新進度時通知。
4. 不再使用的區域函式 WakeOrganization。

通知仍只入列，忙碌角色繼續保留，受決策預算與同秒限制控制；沒有直接呼叫 Planner、替 NPC 下指令或改變玩家控制權限。
