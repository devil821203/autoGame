## 範圍與決策

依 [R3 執行方案](R3_事件決策與知識邊界_執行方案_20261110.md)，補組織策略依賴的資產、人力與聚落公共規劃變更喚醒。只改重新評估的觸發，不新增組織策略、治理權限、資產規則或資訊廣播玩法。

- `EventDecisions.OrganizationChanged`：查實際組織的現任 LeaderId，只對存在、存活且非怪物的領袖加入 StateChanged。未知帳戶、沒有領袖或沒有啟用 R3 時不處理；不向全體成員廣播私人庫存。
- `EventDecisions.SettlementPlanningChanged`：公共人口、容量或居民配置改變時，取該聚落公共組織、據點組織及建築所有組織，去重並固定排序，再通知其現任領袖。沒有該聚落管理關係的角色不因這條路徑收到通知。
- 繼續沿用既有 Request 去重、FIFO、同秒限制與忙碌保留，不在生產／交易流程中直接呼叫 Planner 或提交 NPC 行動。

| SettlementDailyEconomy.cs | 消費量大於零、實際消耗與取得收入後通知聚落組織領袖 |
| SettlementPopulationGrowth.cs | 實際新增人口／工作人口時通知該聚落管理者，不因只有增長進度改變而喚醒 |
| PopulationInvestmentActions.cs | 扣除投入資源後通知出資組織；成功新增人口時才通知聚落管理者 |

| OrganizationLaborActions.cs | 真實招募／雜役配置變更、應付薪資的已付／欠付狀態通知組織領袖；零人薪資不額外喚醒 |
| ResourceRegeneration.cs | 資源實際再生後，若資源帳戶組織有領袖則通知；保留原本當地觀察者通知 |

欠薪／停產通知表示新的營運狀態，不表示已扣款；既有付款、產出、失敗與預算規則均未變更。私有建築升級及據點配額只通知其所有者，不把私人財務更新散播給其他聚落組織。

## 待驗證清單（均未執行）

1. 建置、原有 R3 專項與完整回歸；不得引用前批通過數代替本批結果。
2. 組織出／入帳只通知各自現任領袖；非成員、一般成員、無管理關係或生命為零的領袖不誤通知。
3. 多組織由同一領袖管理、同秒多筆生產／稅收／付款時，請求去重、順序、預算與忙碌保留正確。
4. 組織收到資源後，自主建造／招募能在既有資格與預算下重新評估；不產生額外免費資源或越權指令。
5. 工資不足、欠付雜役薪資時，通知不改變原「不付款／不產出」結果；沒有收支或營運狀態變更時不誤通知；重複同日結算不產生重複通知。
6. 人口／住房容量／居民配置實際改變才通知有管理關係的領袖；增長失敗、僅改進度或相同配置不誤通知。
7. 公共規劃與私人資產的通知邊界、JSON／SQLite 快照續算及存檔完整性。
