# 新增測試：收購節點、副本與宗門運作

2026-10-17。由使用者明確要求新增，獨立於先前已結案Demo；未變更正式地圖系統的待確認狀態。

## 使用方式

Godot建置後F5，在「建立情境」輸入角色名稱，按「宗門經濟／副本測試」。會重建記憶體世界，先另存需要保留的進度；原「建立角色／階段4 Demo」不啟用本批測試規則。

- 「宗門運作」查看外部收購、當輪進度／價格、宗門資金／庫存、俸祿、各成員缺交次數與下次考核。
- 「地圖Demo」前往打怪副本，推進旅行完成後，按上方「探索打怪副本」。遇怪即進入既有固定Tick戰鬥；戰鬥頁可強擊／治療／撤退。沒有遇怪時記錄DungeonEmpty，可再探索。
- 「宗門任務」查看自動任務；到宗門後可接受與交付1份。NPC仍自行評估接取、供貨、旅行與探索，並非強制指定工作。
- 事件查詢可用 PayrollPaid／PayrollSkipped／DutyReviewed／DutyExpelled／DungeonEncounter／TestProcurementBought／ProcurementPriceReviewed 等類型篩選。

## 已確認規則

| 系統 | 規則 |
|---|---|
| 測試收購 | 僅向宗門庫存收購；每輪目標回春丹100、狼皮100，允許超收；使用者確認無資金上限 |
| 調價 | 每20Tick檢查該輪實收，未滿目標加價、超過目標降價、恰好達標不變，之後重新計數；新報價適用下一輪 |
| 俸祿 | 每10Tick，普通成員／長老每人30靈石，不含宗主 |
| 自動任務 | 每20Tick自動發布回春丹／狼皮成員任務；沿用預算保留、期限、多人交付與付款 |
| 考核 | 每名成員每30Tick至少一次成功交付；連續3期未交付逐出；該期成功交付清零；宗主不考核 |
| 副本 | 有機率遇山匪或狼；山匪高機率1–5靈石、低機率丹藥；狼只狼皮 |

## 可設定候選數值與邊界行為

未另確認的數值為可設定測試預設，不升格最終平衡：

- ProcurementRules：初價回春丹150、狼皮30；每次漲跌10%，變動至少1、價格上下限1–1,000,000。每Tick自動收購宗門目前持有數量，不以100截斷；第20Tick先收購再檢查本輪。無貨仍會在期末檢查缺額並加價。收購節點在地圖為自動服務標記，不需玩家抵達或操作。
- DungeonRules：遭遇率80%，遇到後狼／山匪各50%；山匪80%掉1–5靈石，10%掉1丹，兩者獨立判定可同時掉或都不掉；狼固定1狼皮。怪物初始生命40、攻擊4、防禦1。探索目前為即時一次判定，遭遇後花費既有戰鬥回合時間；沒遇到不額外收費。戰鬥失敗／撤退不發勝利戰利品。
- SectDutyRules：每種任務預設20份，丹藥報酬120／狼皮15，期限為下一發布週期。已有同商品有效任務時不重複；資金不足時縮小數量，連一份都無法支付則記事件跳過，不產生無預算任務。這是組織政策自動發布，不會替玩家或NPC強行接單。
- 新加入成員從登記時起享完整30Tick考核週期，不補計入門前的缺交。任一宗門任務的成功交付收據（實際交付>0）算當期完成一次，不是光按接受；沿用使用者確認的「成功交付」口徑。未發得出任務／資金不足不自動豁免考核。退出／逐出移除考核記錄，再加入重新起算。
- 俸祿不動用任務保留款；若可用資金或任一收款者容量不足，整批不支付並記PayrollSkipped，沒有建立欠薪／追補機制。同Tick先處理玩家／NPC行動，再收購、考核／自動任務、最後俸祿，已逐出者不領當次俸祿。
- AI依自己缺交次數與俸祿價值增加任務留任誘因；仍排除不可行行動，不保證每名NPC都成功履約。狼皮任務估算健康／風險與遇狼機率，探索與入戰均用共用規則；無全知保證掉落。

數值由WorldState中的TestProcurement／Dungeon／SectPayroll／SectDuty保存，可透過情境設定及JSON調整，無新增UI數值編輯器。

## 帳本、來源及存讀

無限收購明確使用 `$test-procurement` 外部測試來源：先注資給收購節點，再宗門出貨與節點付款；ProcurementReceipt與三筆帳本互相驗證，不能把新增測試貨幣宣稱守恆。怪物物資於遭遇時由 `$dungeon` 可追溯來源生成到怪物庫存，勝利後從怪物轉移至勝者，保留戰利品收據；山匪不掉藥材，狼不掉靈石或丹藥。重複意圖沿用去重，不能重複產怪或支付。

俸祿、任務支付由宗門帳本扣款。收購輪內累計、報價、交易收據、考核週期／缺交次數、怪物、戰鬥與亂數狀態全部存檔。新增資料採可選欄位，舊schema2存檔不啟用本批規則；既有schema1→2遷移保留其他資料。沒有改寫使用者舊存檔。
