# 組織自動擴建與升級：實作與驗收

2026-10-23，限定新建「村內組織測試」的柳溪幫，不遷移舊檔。使用者確認順序為農田、林場、礦場各一座，建齊後生產建築升至2級；配額不足才升總舵，最高2級。保留100錢財及20木材，補聘可用居民，不自動買賣或補資金。

設定入口為 `config/settlements/organization-development.json`；啟動時驗證並保存世界快照。費用、員工上限與產量沿用現有設定。唯讀決策位於 `src/Simulation/OrganizationDevelopmentDecisions.cs`，由自主排程提交原有指令，仍經資格、位置、AP、庫存與配額驗證。首領有可執行管理工作時優先處理，離村時規劃返回，沒有直接修改經濟狀態。一般AI行動在管理目標完成或資源不足後繼續運作。

補聘優先於新建／升級；員工取自聚落可用居民，並不新增人口。總舵升級會同步同聚落組織場景的主建築展示等級。初始配額3恰好容納三棟，因此正常測試總舵維持1級是預期行為。

保留量是自主發展支出的門檻，不是鎖定庫存；既有每日工資仍照常支付。沒有銷售收入的組織長期可能耗盡資金停工，不能將本次建設能力視為經濟自給。首領一般戰鬥／治療行為未擴充。

驗收：專項4/4通過（自主建造／聘員／升級及存讀、保留量與舊快照、配額壓力升總舵及展示同步、非法設定拒絕）。測試中的較小初始配額只用於測試世界快照，不改動正式config。完整回歸與一年結果另於完成後補記。

執行：`dotnet run --project tests/Acceptance --no-restore -- --organization-development-only`。Godot選「村內組織測試」，開始自動推進後查詢組織建築及資產；需新建情境才載入新config。人工畫面操作未驗證。
