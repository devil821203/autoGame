# 六角地圖首版：實作與驗收

更新：2026-10-17。範圍為已授權的固定六角世界、分層初始領地、旅行、宗門建造及既有工作整合。未實作領地擴張。

## 1. 如何使用

1. 用 Godot 4.3 .NET 開啟 `src/Presentation/project.godot`，執行專案。
2. 保存目前進度，再按「六角世界／領地測試」建立獨立新世界。此測試情境將玩家設定為青雲宗宗主，舊存檔不改寫。
3. 選「六角世界」頁籤：左鍵選取地塊、滾輪縮放、中鍵拖曳。
4. 按「旅行至選取地塊」，前進一 Tick 提交，再繼續推進時間。金點表示玩家目前格，金線表示尚未完成的路徑；到達每一格才更新核心座標。
5. 抵達青雲宗 `(4,2)` 後，選取宗門地塊並按「進入青雲宗場景」，可使用既有任務、兌換及治理入口。內部場景目前只有青雲宗，其他據點沿用既有功能面板。
6. 興建可先選青雲宗領地空格 `(4,3)`，選藥園或煉丹房，按「宗門興建」，再推進 Tick。施工中選同格可取消，全額退回組織保留款；完工後不能取消退款。
7. 新建藥園／煉丹房完工後，旅行至該格，再從「宗門設施與兌換」頁執行工作。仍須先在宗門接對應工作，並符合能力、材料與成員資格。

建造使用抽象排程，首版沿用角色排程的忙碌限制：下令角色在施工期間不能開始旅行或其他排程工作，可先取消施工。現有 NPC 會自主旅行與工作，尚未新增首領 AI 自動選址建造。

## 2. 實際地圖與領地規則

- 測試圖為 10×8、80 格，尖頂六角、軸向 `(q,r)`、有限且不環繞。
- 地表分為平原／沙漠／湖泊，山脈與森林為獨立特徵；村莊、城鎮與據點疊加其上。
- 平原 1 Tick、森林 2 Tick、沙漠 3 Tick；山脈與湖泊不通行。這些是候選測試值，並非最終平衡。
- 使用穩定排序的 Dijkstra 最低成本路徑；不是只畫直線，也不以畫面動畫完成判定抵達。
- 對應五個既有位置：青雲鎮 `(2,3)`、青雲宗 `(4,2)`、藥園 `(5,3)`、煉丹房 `(5,2)`、副本 `(5,5)`；柳溪村僅為聚落標記，未新增村莊經濟。
- 紫色標示國家管轄，青／橙／紅標示宗門／幫派／山寨地方領地；同一層每格僅一個組織，國家層可與地方層重疊。
- 國家層首版用於表達管轄，不對既有地方領地額外加建造禁令或通行費；稅制、外交、道路、飛行與船舶未實作。
- 固定測試地形與初始邊界作為開局公開圖資；NPC 的收益評估仍只接收既有觀察，沒有因此取得全球庫存、其他角色私有記憶或未知市場價格。
- 四類組織已有類型與初始領地資料；國家／幫派／山寨的特色服務與建築仍待確認，不能視為四套完整可玩系統。

## 3. 建造與經濟

已確認並實作：每格一棟主要建築、只耗組織靈石、抽象 Tick 工期、完工前取消全退。首版只開放宗門藥園及煉丹房：

| 建築 | 候選成本 | 候選工期 | 實際效果 |
|---|---|---|---|
| 宗門藥園 | 100 靈石 | 8 Tick | 在新格提供既有宗門採藥工作入口 |
| 宗門煉丹房 | 200 靈石 | 12 Tick | 在新格提供既有宗門煉丹工作入口 |

開局既有藥園與煉丹房映射為已完工建築，維持經濟循環。新增設施共用原有草藥資源池、宗門庫存及工作結算，不複製資源、不產生另一份宗門庫存，也不因多一棟建築就增加免費產出。

只有所屬組織首領可在己方地方領地合法空格下令。開工即從組織帳戶轉入保留帳戶；完工才消耗，取消退回組織，保留款與結算均可稽核、防重放。施工中領地失效會停工保留款項，可取消，不自動轉移建物與資產。首版沒有提供變更領地的遊戲操作，此失效保護由核心驗收模擬。

```powershell
dotnet build src/Presentation/CultivationGame.csproj --no-restore
dotnet run --project tests/Acceptance --no-restore
& '.tools/godot43/Godot_v4.3-stable_mono_win64/Godot_v4.3-stable_mono_win64_console.exe' --headless --path src/Presentation -- --hex-world-smoke
```

最終建置 0 警告、0 錯誤，核心 **149/149 passed**（原140項＋9項六角案例）。原始輸出見 [驗收日誌](evidence/hex-map-core-149-20261017.log)。

Godot 場景驗收涵蓋選格、旅行、宗門內部場景同步、建造／取消、存讀及繪圖不推進世界；既有 `SECT_SCENE`、`MAP`、`SECT_FACILITY` UI 回歸通過。所有這些均是 Headless 自動驗收，沒有以此宣稱人工視覺或 FPS 通過。

首輪核心 147/148：退款案例未隔離同 Tick 的測試收購收入，將組織餘額錯當純建造變化。隔離該案例的外部收購後 148/148；再補失地停工案例與缺失地圖拒絕檢查。最終結果同步在進度總表，不覆蓋此失敗紀錄。
