## 範圍與預設

新增角色身分、組織歸屬、職位、境界、功法、功法熟練、武器及基礎攻防資料。生命沿用現有 Health；狀態由生命推導為健康／受傷／無法行動，生命 0 的角色不能提交一般行動。本版沒有死亡、復活、戰鬥傷害或受傷懲罰公式。

AdvancementRules 集中養成設定。初版只有一套功法 `qingmu`（青木訣）及一種武器 `iron-sword`；數值是待驗證預設，不視為完整養成平衡或已確認的境界名稱。

| 規則 | 預設 |
|---|---|
| 學習功法 | 20 靈石、3 Tick；只能學習一次 |
| 境界 | 整數 0–3；突破需要已學功法及生命至少 50 |
| 突破修為門檻 | `(目前境界 + 1) × 50`；突破完成扣除對應修為 |
| 突破材料／時間 | 2 顆丹藥、4 Tick；條件通過後必成功，尚未加入突破亂數失敗 |
| 功法熟練 | 完成修煉時增加；每 5 熟練提升一級，已學功法從 1 級起，最高 5 級 |
| 功法修煉加成 | 每功法等級讓每次丹藥修煉額外增加 2 修為 |
| 技能等級 | 煉丹／採集熟練每 10 點一級，從現有熟練推導；原成功率／採集加速規則保留 |
| 基礎攻防 | 預設攻擊 10、防禦 2；每境界攻擊 +4、防禦 +2；每功法等級攻擊 +1 |
| 鐵劍 | 攻擊 +6、防禦 +1；必須持有帳本庫存才可裝備 |

這些攻防目前供觀察及後續戰鬥使用，不宣稱已能造成傷害。

## 共用規則與資料一致性

- LearnMethod、Breakthrough、EquipWeapon、UnequipWeapon 全部經共用 Validator／Executor。玩家只操作指定角色，AI 輸出意圖。
- 學習與突破先把靈石／丹藥移入行動 escrow，完成後轉入 consumed 帳戶；完成前不取得功法或境界。重複提交、忙碌、缺材料、門檻不足及超過境界上限會拒絕。
- 裝備不複製或生成武器，仍以角色帳本持有量為準；必須卸下才能轉移該資源，避免保留不存在裝備的加成。
- 新資料完整性檢查包括身分／職位、組織存在性與領導者一致性、功法與境界、裝備持有、規則範圍及排程資格。尚無招募、任免或組織政策行動，情境初始歸屬是設定資料。
- WorldState.Advancement 預設 null，舊場景不啟用新養成候選及修煉加成；舊存檔的新角色欄位採預設值。仍為 schema 1 新增欄位，沒有正式遷移或降版保證；不同程式版本的序列化雜湊可能不同。
- NPC 觀察只多提供自身可取得的武器數量及養成規則。UtilityPlanner 比較學習成本、成長偏好、耗時、突破門檻及丹藥需求，可自主學習／裝備／購丹／突破；既有計畫保存與失效機制繼續使用。

## Godot 操作

F5 執行後，按「建立階段 3 養成情境」。按鈕會重建記憶體世界並暫停，不覆寫存檔；請先儲存要保留的世界。

進入「開發者 → 養成與裝備」，從角色下拉或角色總表選擇角色，觀察身分、組織、職位、狀態、境界、功法等級、熟練、攻防與裝備。此情境建立 40 NPC，部分角色已有功法，並提供可追蹤初始丹藥／武器，讓自主成長可重現。

玩家初始修為足夠第一次突破，但尚未學功法。按「玩家學功法」後推進時間，完成後按「玩家突破」；可再用裝備／卸下按鈕比較攻防。所有按鈕只排隊，仍須推進 Tick 才生效。NPC 則在「暫停／繼續」後自主選擇行動。
