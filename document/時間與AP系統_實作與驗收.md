# 時間與AP系統：實作及驗收

日期：2026-10-18。適用新建「時間與AP測試」；舊模式與舊存檔不轉換。

## 操作

Godot F5 →「時間與AP測試」→「繼續／暫停」或單步推進Tick。上方顯示年／季／日、日內Tick、目前觀察角色AP與忙碌剩餘Tick。初始暫停，啟動後無須下令也會推世界；玩家沿共用AI自主行動，手動指令優先。優先級排序介面仍待確認。

進副本遇敵，或使用既有交戰指令後，切到「雙陣地戰鬥」下移動／普攻指令，亦可勾「玩家自動戰鬥」。每次推進只處理一個戰鬥輪；戰中世界Tick、休息、生產、薪資及任務期限凍結，戰後自動補5世界Tick。補時正常處理其他角色與工作，不按參戰人數重複補時。若補時觸發新玩家戰鬥，保存原場剩餘補時，待戰後續推。

## 已實作規則

- 1年120日，四季各30日；第1年春季1日起，每日30世界Tick。
- 每角色每日30AP。合法開始一次扣款；不足／拒絕不扣，重複ID不重扣；新日重設30、不累積、不透支。
- 1AP＝1佔用Tick。採藥2：第一Tick開始保留原料，第一Tick末無產出，第二Tick末結算一次，第三Tick才可再動。跨日保留工期及已付成本，新日不重扣。
- 成本：交易／交付／兌換等1、採集2、煉丹／修煉／學習3、休息每Tick1、旅行依六角路徑費率、主動戰鬥5；其他行動預設1。建造在本測試模式也按成本表預設1佔用Tick；舊地圖模式保留建築原工期。成本不足時閒置至可執行，不免費恢復體力。
- 生產材料沿既有保留帳戶與完成流程；即時類指令延後至Tick末重新驗證及提交，若資源／資格已失效，記錄失敗而不退已開始AP。取消既有建造可退未消耗材料保留款，但不退已開始AP。沒有新增任意取消工作功能。
- 休息回復沿已確認每Tick生命10、體力15／30／45、昏厥10；每次實際休息Tick消耗1AP，昏厥當Tick不立即恢復。
- 主動參戰者各付5，防守免費；同宗門隊員沿既有小隊，自主加入者須同地、可行動且AP足夠。探索成本1且開始前預留5AP，遭遇怪物才再扣戰鬥費；未遇敵不扣5。
- NPC戰鬥用相同方格規則無畫面逐輪跑至結束，世界不依戰鬥輪數增加；參戰者占用5Tick，其他NPC正常並行。
- AP收據、排程、跨日日期及戰後剩餘補時隨存檔保存；開新存檔保留時間測試模式，關閉後不離線推進。

## 新情境週期換算

依使用者確認，原設定的週期數字視為「天」後乘30存入新世界快照；不改共用原JSON或舊存檔。

| 設定 | 新情境 |
|---|---|
| 俸祿10 | 每10日＝300Tick，金額仍依目前設定10靈石 |
| 收購價格檢查20 | 每20日＝600Tick；有可售庫存仍可每Tick成交 |
| 宗門任務發布20 | 每20日＝600Tick |
| 考核／任務期限120 | 120日＝3600Tick |
| 清剿、邀請、藥草再生、社交與記憶／計畫期限 | 原數字×30 |
| 手動發布7日期限 | 210Tick，介面與核心一致 |
| 普通行動／旅行／休息 | 使用AP成本，不將動作工期再乘30 |

週期大幅延長會改變現金流，本批驗證時間與資源一致性，尚未驗證新模式長期經濟平衡。

## 檔案與設定

- `src/Domain/WorldTime.cs`：日期、AP、延後指令與戰後補時資料。
- `src/Simulation/TimeScenario.cs`、`TimeActions.cs`、`SimulationEngine.Time.cs`：獨立情境、驗證扣款、Tick開始／末尾流程、戰鬥分時。
- `config/time/calendar.json`：30Tick／日、30AP、戰鬥5AP與最多100輪；`action-costs.json`：各種行動成本。戰鬥成本可設定1～30，補時同步使用該成本；本批驗收預設5。
- `Main.cs`、`MissionPanel.cs`：新情境入口、日期／AP／忙碌與任務期限。
- `tests/Acceptance/TimeTests.cs`：時間及AP案例。設定只於新建載入，存檔保存自身快照。
